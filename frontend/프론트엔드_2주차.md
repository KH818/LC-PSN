# 프론트엔드 2주차 작업 정리

## 1. 작업 목적

기존 placeholder 중심 화면을 백엔드 WebSocket stream과 연결되는 실시간 DOA 대시보드로 발전시켰다.

주요 작업은 다음과 같다.

- `/predict` 직접 호출 제거
- `/health` 기반 서버 연결 확인
- WebSocket 기반 실시간 추론 결과 수신
- 최근 수신 데이터 localStorage 캐시 저장
- Pause Display 기능 추가
- Replay slider 기능 추가
- Event Log 패널 추가
- Data freshness 표시 추가
- WebSocket 자동 재연결 추가
- 화면 렌더링 throttle 추가
- Spectrum/Waterfall 렌더링용 downsampling 추가
- Polar, Spectrum, Waterfall chart 구현
- Vite 기본 화면 제거 및 대시보드 레이아웃 정리

## 2. 현재 데이터 흐름

```text
백엔드 서버 시작
-> H5StreamInference 실행
-> train_mini_1bit.h5에서 샘플 로드
-> mock_predict()로 추론 결과 형태의 mock 데이터 생성
-> WebSocket broadcast
-> frontend useWebSocket에서 수신
-> React state / localStorage cache 갱신
-> chart와 panel 렌더링
```

현재 `.h5` 파일은 읽고 있지만, 화면에 보이는 추론 결과는 실제 모델 출력이 아니라 `mock_predict()`에서 만든 mock 결과다.

## 4. 주요 함수와 컴포넌트

### 4.1 `useWebSocket(url, { paused })`

파일:

```text
frontend/src/hooks/useWebSocket.js
```

역할:

- WebSocket 연결 생성
- 연결 상태 관리
- 최신 메시지 저장
- 최근 메시지 history 저장
- 마지막 수신 시각 저장
- localStorage cache 저장 및 복구
- Pause Display 상태 처리
- WebSocket 종료 시 자동 재연결
- WebSocket 수신 빈도가 높아질 때 화면 렌더링 빈도 제한

반환값:

```js
{
  status,
  message,
  messageHistory,
  lastMessageAt,
  reconnectAttempt,
  error,
}
```

캐시 정책:

```text
latest: 가장 최근 추론 결과 1개
history: 최근 추론 결과 최대 50개
```

Pause Display 동작:

```text
Pause Display ON
-> WebSocket 연결은 유지
-> 새 메시지는 cache/ref에는 저장
-> 화면 state는 갱신하지 않음

Pause Display OFF
-> pause 중 받은 최신 메시지와 history를 화면에 동기화
```

자동 재연결 동작:

```text
WebSocket close
-> status = reconnecting
-> 1초 뒤 재연결
-> 실패 시 2초, 4초, 8초 간격으로 재시도
-> 연결 성공 시 reconnectAttempt 초기화
```

렌더링 throttle 동작:

```text
WebSocket message 수신
-> cache/ref 즉시 갱신
-> localStorage 즉시 갱신
-> React 화면 state 업데이트는 최소 500ms 간격으로 제한
```

현재 백엔드는 3초 주기라 차이가 크지 않지만, 실제 모델이 더 빠른 주기로 결과를 보낼 경우 불필요한 chart 렌더링을 줄일 수 있다.

### 4.2 `normalizeInferenceEvent(event)`

파일:

```text
frontend/src/utils/inferenceEvent.js
```

역할:

백엔드 event 구조를 프론트엔드 chart가 사용하기 쉬운 공통 구조로 변환한다.

현재 mock event:

```json
{
  "type": "stream_inference_result",
  "data": {
    "estimated_k": 3,
    "doas_deg": [-31.2, 9.8, 42.1],
    "confidence": 0.91,
    "spectrum": []
  }
}
```

프론트엔드 내부 공통 구조:

```js
{
  eventId,
  type,
  timestamp,
  sensorId,
  kEstimate,
  doas,
  peakScores,
  confidence,
  spectrum,
  sampleIndex,
  inputFile,
  streaming,
}
```

이 함수를 통해 현재 mock 구조와 향후 정식 event 구조를 chart component에서 같은 방식으로 처리할 수 있다.

### 4.3 `downsampleNumberList(values, maxPoints)`

파일:

```text
frontend/src/component/charts/chartUtils.js
```

역할:

긴 spectrum 배열을 화면에 그릴 때만 축소한다. 원본 WebSocket 데이터와 localStorage 캐시는 그대로 유지한다.

현재 적용 위치:

- `SpectrumChart`: 최대 360개 point만 렌더링
- `WaterfallChart`: frame당 최대 240개 column만 렌더링

처리 방식:

```text
긴 배열을 일정 크기 bucket으로 나눔
-> 각 bucket에서 가장 큰 값을 선택
-> peak가 사라지지 않도록 렌더링용 배열 생성
```

이 방식은 국방/전파 탐지 화면에서 중요한 peak 위치를 최대한 살리면서 DOM/SVG 렌더링 비용을 줄이기 위한 최적화다.

```text
frontend/src/component/charts/SpectrumChart.jsx
```

역할:

spectrum 배열을 line chart로 표시한다.

주요 처리:

- spectrum 숫자 배열 정리
- 화면 렌더링용 downsampling
- y축 범위 계산
- SVG polyline 좌표 생성
- spectrum area와 line 표시
- header에는 원본 bin 개수 표시

### 4.7 `WaterfallChart`

파일:

```text
frontend/src/component/charts/WaterfallChart.jsx
```

역할:

최근 spectrum history를 heatmap 형태로 표시한다.

주요 처리:

- `messageHistory`에서 spectrum 추출
- 최근 최대 36개 frame 사용
- frame당 화면 렌더링용 column을 최대 240개로 제한
- 값이 클수록 따뜻한 색에 가깝게 표시
- Replay 중에는 선택 frame 기준 이전 history window 표시

### 4.8 `ReplayPanel`

파일:

```text
frontend/src/component/panels/ReplayPanel.jsx
```

역할:

최근 history를 slider로 탐색한다.

동작:

```text
slider 이동
-> replayIndex 변경
-> 해당 frame chart 표시
-> Waterfall은 선택 frame 기준 이전 최대 36개 history 표시
```

`Back to Live` 버튼을 누르면 Replay mode를 종료하고 최신 live 화면으로 돌아간다.

### 4.9 `EventLogPanel`

파일:

```text
frontend/src/component/panels/EventLogPanel.jsx
```

역할:

최근 history를 비교해 의미 있는 변화를 sidebar에 기록한다.

감지 기준:

- K estimate 변경
- source count 증가
- source count 감소
- DOA 최대 이동량 10도 이상
- confidence 80% 미만
- confidence 12%p 이상 하락

### 4.10 `ConnectionStatusPanel`

파일:

```text
frontend/src/component/panels/ConnectionStatusPanel.jsx
```

표시 항목:

- API URL
- WebSocket URL
- 연결 상태
- Display mode
- Reconnect attempt
- Data freshness
- Data age
- 수신 메시지 수
- 마지막 수신 시각

Data freshness 기준:

```text
0~5초: fresh
5~10초: delayed
10초 이상: stale
수신 없음: waiting
```

이 기능은 실제 운용 환경에서 데이터가 최신인지, stream이 지연되고 있는지 빠르게 확인하기 위한 요소다.

## 5. 프론트엔드 캐시 구조

localStorage key:

```text
lcpsn:inference-cache:v1
```

저장 구조:

```js
{
  version: 1,
  latest,
  history,
  lastMessageAt,
}
```

캐시는 화면 표시를 지연시키는 큐가 아니라 보조 저장소다.

목적:

- 새로고침 후 마지막 화면 복구
- Waterfall history 복구
- Replay frame 복구
- WebSocket 연결 전 빈 화면 방지

## 6. 백엔드 mock 데이터 변경

`mock_predict()`는 반환 데이터 규격을 유지하면서 값 생성 방식만 더 현실적으로 바꿨다.

유지한 반환 필드:

```text
estimated_k
doas_deg
confidence
spectrum
message
```

변경 의도:

- 완전 랜덤 K/DOA 대신 안정적인 신호원이 일정 시간 유지되도록 함
- 중간에 신규 신호원이 출현하도록 함
- 특정 target 방향 peak가 점진적으로 낮아지는 흐름을 spectrum에 반영
- 데이터 규격은 기존과 동일하게 유지
